# История измерений — дизайн и влияние на быстродействие

## Цель

Список последних результатов программ (СЖАТИЕ / РАЗРЫВ): **дата**, **результат** (выполнено / остановлено пользователем / ошибка), **итоговый вес (Н)**. Хранение между перезагрузками, без ухудшения быстродействия.

## Модель данных

**Одна запись:**
- `timestamp` — Unix time (uint32_t), от NTP при синхронизации, иначе 0
- `programType` — 1 = СЖАТИЕ, 2 = РАЗРЫВ (uint8_t)
- `outcome` — 0 = выполнено, 1 = остановлено пользователем, 2 = ошибка (uint8_t)
- `weight` — итоговый вес, Н (float)

**Итоговый вес:**
- СЖАТИЕ: максимум за измерение — `TenZillaDisplay::getMainScreenMax()`
- РАЗРЫВ: максимум за измерение — `TenZillaProgram::breakMaxWeight` (в момент завершения)

**Результат (outcome):**
- **Выполнено** — программа дошла до целевого перемещения (сжатие) или до падения после максимума (разрыв).
- **Остановлено пользователем** — вызван `stopProgram()` (кнопка стоп на TFT или веб).
- **Ошибка** — сработали ограничения (перемещение или перегрузка), `limitExceeded` в `Program::update()`.

## Когда записывать

Запись **только** при завершении программы:

1. **Успех (СЖАТИЕ):** в `Program::update()`, при `workingDisplacement >= compressionTargetDisplacement` — перед `stopProgram()`.
2. **Успех (РАЗРЫВ):** в `Program::update()`, при падении `dropPercent >= breakDropThreshold` — перед `stopProgram()`.
3. **Ошибка:** в `Program::update()`, в блоке `limitExceeded` — перед сбросом состояния (`programType` и т.д.).
4. **Остановка пользователем:** в `stopProgram()`, при установке `programStoppedManually` — до обнуления `programType` и флагов.

Во всех остальных местах (цикл опроса весов, веб-опрос, отрисовка) код **не** вызывается — нет нагрузки на горячий путь.

## Хранение

- **NVS** (namespace `tenzilla-meas`), один ключ `meas` — бинарный блок.
- Формат: `[uint16_t head][uint16_t count][entry_0]...[entry_49]`, каждая `entry` = 10 байт (timestamp, type, outcome, weight). Всего до 50 записей, кольцевой буфер; размер блока < 508 байт, укладывается в лимит NVS.
- **RAM:** копия буфера в статическом массиве. При записи — обновление RAM и одна запись в NVS. При старте — загрузка из NVS в RAM.
- **Чтение для API:** только из RAM, без обращений к NVS при каждом запросе.

## Быстродействие

| Операция | Когда | Влияние |
|----------|--------|---------|
| Запись в NVS | Только при завершении программы (редко) | Несколько миллисекунд раз в минуты/часы, не в цикле опроса весов |
| Чтение из NVS | Один раз при загрузке | Стартовая задержка, не критично |
| `GET /api/measurements` | По запросу веб-клиента | Чтение из RAM, формирование JSON, без диска |
| Опрос весов, двигатель, отрисовка | Как сейчас | Без изменений |

Итог: цикл измерений, веб-опрос и UI не затрагиваются; дополнительная работа только при завершении программы и при явном запросе истории.

## API и веб

- **`GET /api/measurements`** — JSON-массив записей (от новых к старым). Вызывается только при открытии вкладки «История» и по кнопке «Обновить» (без фонового опроса).
- Вкладка **«История»** в веб-интерфейсе: таблица — дата, тип (СЖАТИЕ/РАЗРЫВ), результат (Выполнено / Остановлено / Ошибка), вес (Н). Данные подгружаются при переходе на вкладку.

## Расширения (опционально)

- Настройка максимального числа записей (например, 20 / 50 / 100) и хранение в несколько ключей NVS при необходимости.
- Экспорт в CSV через веб или отдельный эндпоинт.
- Показ истории на TFT (отдельный экран или подэкран в «Прочие»).
